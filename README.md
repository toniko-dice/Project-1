# EcoFlow България

Витрина на продуктовата гама с админ панел за редакция. Покупката се извършва във външен магазин — сайтът не обработва плащания.

## Стартиране

```bash
npm run dev
```

- Сайт: http://localhost:3000
- Админ панел: http://localhost:3000/admin

Данни за вход след `npm run seed`:

| | |
|---|---|
| Имейл | `admin@ecoflow.bg` |
| Парола | `EcoFlow2026!` |

**Сменете паролата при първо влизане.**

---

## Промяна на схемата — прочетете преди да пипате полета

Автоматичното напасване на базата (`push`) е **изключено**. Всяка промяна по поле, колекция или блок минава през миграция. Иначе базата задава интерактивни въпроси и рискува да загуби данни.

Работният ред е:

```bash
npm run migrate:create
```
```bash
npm run migrate
```

Между двете отворете новия файл в `src/migrations/` и го прегледайте — там се вижда точно какво ще стане с данните.

Другите команди:

```bash
npm run migrate:status
```

`migrate:fresh` изтрива всичко и пуска миграциите от нула. Ползвайте го само на празна база.

## Дизайн

### Цветове от админа

**Настройки → Дизайн**

Всички цветове на сайта се сменят оттам, без пипане на код и без нов билд. Празно поле означава „ползвай стойността по подразбиране“.

Разделено е на пет таба: *Марка* · *Фонове* · *Текст и линии* · *Тъмни банери* · *Сигнални цветове*.

Ефектът на потъмняване при посочване се управлява от **Фонове → Плочки при посочване**.

### Цветове в кода

Стойностите по подразбиране са в `src/app/(frontend)/globals.css`, в блока `@theme`. Това е единственото място в кода, където стои шестнайсетичен цвят.

Всеки токен ражда истински Tailwind клас:

```
--color-tile  →  bg-tile, text-tile, border-tile
--color-ink   →  text-ink, bg-ink, border-ink
```

**Не пишете `bg-[--color-tile]`.** Тази скоба е синтаксис от Tailwind 3; в 4 дава невалидно правило, което браузърът мълчаливо изхвърля — стилът изглежда приложен в кода, но не прави нищо. Пишете `bg-tile`.

Шрифтове: **Rubik** за заглавия, **Nunito Sans** за текст. И двата покриват кирилица.

## Съдържание

### Секции на страницата

**Съдържание → Страници → Начало**

Страницата е списък от секции. Всяка се добавя, мести с дръжката вляво, или трие от менюто вдясно.

| Секция | За какво служи |
|---|---|
| Главен банер | Големият банер най-отгоре |
| Лента с категории | Редът с кръгли икони |
| Продуктов карусел | Хоризонтално превъртащ се ред |
| Банер + продукти | Банер и ред продукти под него. Основният повтарящ се модел |
| Промо карти | Две или три карти една до друга |
| Широк банер | Единичен банер през цялата ширина |
| Предимства | Ред с икони и кратки текстове |
| Отзиви | Карти с отзиви от клиенти |
| Лога и отличия | Ред с лога на награди |

### Мега менюто

Разделено е на две, за да не се рови надълбоко:

**Меню → Панели в менюто** — съдържанието. Един запис за всяка подточка (Серия DELTA, PowerOcean…). Отваряте го и виждате всичките му карти и снимки наведнъж.

**Меню → Меню (хедър)** — само скелетът: главните точки, групите в сайдбара, и коя подточка към кой панел сочи. Четири таба: *Лента най-горе* · *Лого* · *Точки в менюто* · *Бутон и търсене*.

Структура на един панел:

```
Панел (напр. „Серия EcoFlow DELTA")
└─ Секции (напр. „Серия DELTA", „Аксесоари")
   ├─ Заглавие + линк „Виж всички"
   ├─ Голяма карта вляво (незадължителна)
   ├─ До 5–6 малки карти
   └─ Плочка „Виж всички" в края
```

Всяка карта има снимка, име, ред със спецификации, адрес, син етикет над името и оранжев бадж върху снимката.

### Продукти

**Каталог → Продукти**

Цените се въвеждат **в евро**. Левовата равностойност се смята автоматично по фиксирания курс 1,95583. Двойното показване се изключва от *Настройки → Общи настройки*.

Ако попълните **Стара цена**, тя се показва зачертана и отстъпката се пресмята като процент.

### Категории

**Каталог → Категории**

Категориите са на две нива. Главна категория („Портативни електроцентрали") и серия под нея („Серия DELTA"), закачена чрез полето **Подкатегория на**.

## Архиви

**Настройки → Архиви**

Над списъка има поле за име и бутон **„Създай архив сега"**. Всеки архив съдържа базата (продукти, категории, менюта, страници, текстове) и папката със снимките.

Пазят се **последните 10**. По-старите се трият автоматично.

Освен ръчния бутон, всяка нощ в 03:00 се прави автоматичен архив — но само ако сървърът върви в този момент.

### Свалете копие

Архивите лежат на същия диск като сайта. Това пази от грешка при редакция, но не и от отказ на диска. Отворете архив и свалете файла на компютъра си.

### Възстановяване

Отворете архива и натиснете **„Възстанови от този архив"**. Иска потвърждение, защото заменя цялото съдържание.

Преди замяната автоматично се прави архив на текущото състояние — има връщане назад.

**След потвърждение спрете сървъра и го пуснете отново.** Възстановяването се прилага при старта, защото файлът на базата е зает докато сървърът работи.

Ако се размислите преди рестарта, изтрийте папката `.restore-staging` в корена на проекта — нищо няма да се промени.

## Имейли (заявките за оферта)

Страницата `/oferta-za-firmi` праща два имейла за всяка заявка: вътрешен до
`QUOTE_NOTIFY_TO` (по подразбиране support@dice.bg; „Отговор" отива при
клиента) и копие до клиента. Изпращането е през SMTP (адаптерът на Payload
за nodemailer). Настройките са в `.env` — виж `.env.example`.

**Локално** писмата не излизат от машината:

```bash
npm run mail:catcher
```

и в `.env`: `SMTP_HOST=127.0.0.1`, `SMTP_PORT=1025`, `SMTP_SECURE=false`.
Всяко писмо се записва в `tmp-mail/` — `.html` се отваря в браузъра.

**На сървъра** — истински SMTP (на пощенския доставчик на домейна) и
`MAIL_FROM=EcoFlow България <noreply@bg-ecoflow.com>`. За да не отиват
писмата в „Спам", домейнът bg-ecoflow.com трябва да има в DNS:

| запис | какво | пример |
|---|---|---|
| **SPF** (TXT на `bg-ecoflow.com`) | кои сървъри могат да пращат от името на домейна | `v=spf1 include:<доставчика> -all` |
| **DKIM** (TXT на `<селектор>._domainkey.bg-ecoflow.com`) | публичният ключ, с който доставчикът подписва писмата | дава го доставчикът |
| **DMARC** (TXT на `_dmarc.bg-ecoflow.com`) | какво да правят получателите с неподписано писмо | `v=DMARC1; p=quarantine; rua=mailto:dmarc@bg-ecoflow.com` |

Започнете с `p=none` за седмица-две (само отчети), после `quarantine`.
Адресът `noreply@` не е нужно да е пощенска кутия, но доставчикът трябва да
позволява пращане от него. Проверка след настройката: изпратете тестова
заявка до Gmail и вижте „Показване на оригинала" — SPF, DKIM и DMARC трябва
да са PASS.

## Заключен достъп

Докато сайтът се подготвя, го виждат само влезлите потребители на админа.
Отметката е в „Общи настройки" → „Заключен достъп" (вижда я само
администраторът); по подразбиране е включена — новият сървър тръгва
заключен. Посетителят вижда `/vhod` и влиза със същия имейл и парола като в
админа; един вход важи и за сайта, и за админа. `/api/*` без вход дава 401,
`robots.txt` — `Disallow: /`.

- **Забравена парола** — линкът на `/vhod` (стандартният имейл на Payload;
  иска работещ SMTP).
- **Авариен ключ** — `SITE_GATE=force-off` в `.env` и рестарт: сайтът е
  отворен, каквото и да пише в админа. Махнете го след това.
- **Последна резерва** — `npm run admin:nova-parola <имейл>` на сървъра
  сменя паролата направо в базата и я изписва.
- Локално (`npm run dev`) заключването е изключено; `SITE_GATE=force-on`
  в `.env.local` го включва.

## Какво още не е направено

- **Категорийни страници (`/categories/[slug]`) не съществуват.** Всички линкове от менюто водят натам и в момента дават 404. Това е следващата стъпка
- Продуктови страници (`/products/[slug]`)
- Търсачката в хедъра е визуална, без функционалност
- Формата за бюлетин не е свързана с услуга за имейли
- Правните страници и банерът за бисквитки
