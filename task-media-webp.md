# Задача: WebP за всички размери, оригиналът остава непокътнат

Засяга само `src/collections/Media.ts`.

---

## Проблемът

В `Media.ts` стои:

```ts
upload: {
  imageSizes: [
    { name: 'thumbnail', width: 400, height: 400, position: 'centre' },
    { name: 'card', width: 768, height: 768, position: 'centre' },
    { name: 'banner', width: 1920, height: 900, position: 'centre' },
    { name: 'wide', width: 2400, height: 800, position: 'centre' },
  ],
  formatOptions: { format: 'webp', options: { quality: 82 } },
}
```

`formatOptions` на това ниво важи **само за главния файл**. Всеки размер
има нужда от собствен. Затова главният файл излиза `.webp`, а
`thumbnail`, `card`, `banner` и `wide` остават `.png` или `.jpg` — точно
тези, които сайтът реално показва.

Проверено на живо: продукт с качен PNG дава главен файл `.webp` и четири
размера `.png`.

---

## Решението

**Обърни настройката.**

### Махни `formatOptions` от горното ниво
Оригиналът остава такъв, какъвто е качен — JPG си остава JPG, PNG си
остава PNG.

Причината: това е архивът. Ако утре потрябва друг формат, други изрезки
или по-високо качество, има от какво да се направят. Конвертиран
оригинал е загубен безвъзвратно.

Като страничен ефект оригиналът върши работа и на браузър без поддръжка
на WebP — без да се дублира нищо, защото файлът се пази така или иначе.

### Добави `formatOptions` на всеки размер

```ts
imageSizes: [
  {
    name: 'thumbnail',
    width: 400,
    height: 400,
    position: 'centre',
    formatOptions: { format: 'webp', options: { quality: 82 } },
  },
  // същото за card, banner и wide
]
```

Качество 82 за всички — същото, което е зададено сега.

Остави коментар над блока, който обяснява защо горното ниво е празно.
Иначе следващият ще реши, че е пропуск, и ще го „поправи" обратно.

---

## Важно: старите изображения не се преобразуват

Payload прилага настройките при качване. Деветдесет и четирите
изображения, които вече са в Медия, **остават както са.**

Не пиши скрипт за преобразуване. Те са автоматично генерирани
заместители от seed скрипта и ще бъдат заменени с истинските снимки.
Не си струва да се пипат.

Ако по-късно потрябва, преобразуването става с повторно качване през
админа.

---

## Какво да НЕ правиш

- **Не пази копия в двата формата.** WebP се поддържа от 97-98% от
  браузърите. Дублирането умножава по четири размера, по стотици
  продуктови снимки, и после по всеки архив. Няколко гигабайта заради
  два процента посетители
- Не пипай `next.config.ts` — `formats: ['image/avif', 'image/webp']`
  там е за доставката през `next/image` и е отделно нещо
- Не добавяй AVIF на ниво съхранение
- Не променяй размерите и изрезките

---

## Как да разбереш, че е готово

- Качване на JPG през админа дава: главен файл `.jpg`, а `thumbnail`,
  `card`, `banner` и `wide` — `.webp`
- Същото с PNG: главен `.png`, размерите `.webp`
- В API-то на продукт полето `sizes` показва `mimeType: "image/webp"` за
  всичките четири
- Старите изображения работят както преди — нищо не е счупено
- Няма нужда от миграция; това не е промяна в схемата
