# Миграции, база, архиви

Подробно — `docs/funkcii/resheniya.md` (т. 6, 7, 9, 10, 16, 17). Процедурата — skill `migraciya`.

- **`PRAGMA foreign_keys=OFF` е ПЪРВИЯТ ред на `up()` и `down()`, `=ON` — последният.** SQLite пресъздава таблици; `DROP TABLE` с включени ключове изтрива връзките от другите таблици (`ON DELETE CASCADE`) — миграцията `product_drafts` изяде 72 реда. Генераторът ги слага по двойки — премести ги.
- **Генераторът лъже:** (1) когато таблица губи и печели колони, пита интерактивно и в скрипт НЕ създава файл (код 0) → две миграции: първо добавя, после маха; (2) при пресъздаване чете новите колони от старата таблица → в `SELECT` новите стават `NULL`.
- **`npm run migrate`** = архив + снимка + миграция + снимка. Не го заобикаляй с `payload migrate` (освен върху копие).
- **`src/health-check.ts` чете с чист SQL**, не с `payload.find` — пуска се и преди миграция, когато кодът описва колони, които базата още няма.
- **Архив = `VACUUM INTO`**, не копие на файла. Възстановяването е на две стъпки: разархивира в `.restore-staging` + `restore.json`, замяната е при старт (`src/instrumentation.ts`, `restore-on-boot.ts`) → **рестарт**. Триенето на `-journal`/`-wal`/`-shm` е нарочно. `archiver` е фиксиран на 7.x. Пазят се последните 7 (`KEEP_LAST`).
- **`seed.ts` отказва при поне един продукт** (`-- --force` изрично); скриптът в `package.json` завършва с `--`, иначе `payload run` гълта флага.
- **„database is locked" оставя счупена версия** (редът е записан без децата и е `latest`; следващият запис стъпва на нея). Скрипт, който пише през REST, проверява статуса и спира. При тази грешка — първо „Версии" на засегнатия запис. `busyTimeout: 15_000` в адаптера.
- **Тестове с писане — върху копие** (`DATABASE_URI=file:tmp-….db`, `VACUUM INTO`). **Върху копие не се пуска нищо, което архивира** (`import:all`, `npm run migrate`, бутонът „Архив") — копието трие „своите" стари архиви в общата `backups/` (на 1.10.2026 така изчезна архив № 68). Върху копие: `--dry-run` или `npx payload migrate`.
- След миграция, която пипа съдържание на сайта — опресняване на кеша (`POST /api/products/revalidate` с `x-revalidate-key`) или рестарт; `payload run` не чисти кеша.
- Нова orderable колекция → `npm run backfill:order` след миграцията.
- Включени чернови на колекция със записи → всеки запис трябва да мине през запис (иначе е невидим в админа).
