# Миграция

Правилата — `.claude/rules/migracii-i-baza.md`; историята — `docs/funkcii/resheniya.md` (т. 7, 10).

1. Промяната в полетата е направена; `npm run generate:types`.
2. `npm run migrate:create -- <име>` **в главната папка** (`C:\CLAUDE\ecoflow-bg`). Няма ли „Migration created" — генераторът е искал интерактивен отговор (таблица губи И печели колони) → раздели: първо миграция само с добавяне, после — само с махане.
3. **Прегледай SQL-а:**
   - `PRAGMA foreign_keys=OFF` — ПЪРВИЯТ ред на `up()` и на `down()`; `=ON` — ПОСЛЕДНИЯТ. Генераторът ги слага по двойки около всяка таблица → премести (внимавай да не ги вмъкнеш в параметрите на функцията).
   - При пресъздаване (`__new_…`, `INSERT … SELECT`): новите колони в `SELECT` → `NULL`.
   - `ALTER TABLE … ADD` е безопасно.
4. Копирай миграцията (`.ts`, `.json`, `index.ts`) и `payload-types.ts` в worktree-то.
5. **Проба върху копие:** `VACUUM INTO 'tmp-….db'`, после `DATABASE_URI=file:./tmp-….db npx payload migrate` (НЕ `npm run migrate` — той архивира и трие „старите" архиви в общата папка). Провери данните; изтрий копието.
6. Локалната тестова база: `npm run migrate` (архив + снимка + миграция + снимка; ⚠ на таблица с връзки = изядени редове).
7. На сървъра миграцията се пуска от `npm run deploy` (стъпка 4/7).
8. Нова orderable колекция → `npm run backfill:order`; включени чернови на колекция със записи → всеки запис през запис.
