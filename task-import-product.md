# Задача: скрипт за внасяне на продукт от папка

Този скрипт ще се ползва за всичките 40-50 основни продукта. Направен
веднъж, работи за всеки — затова да е общ, а не за конкретния продукт.

Готов е първият случай за проба: `content/delta-3-classic/`.

---

## 1. Какво има в папката

```
content/<slug>/
  sadarzhanie.json     ← текстове, блокове, съответствие със снимките
  galeryia/            ← снимки за галерията
  sekcii/              ← снимки за секциите
```

Отвори `content/delta-3-classic/sadarzhanie.json` — структурата е описана
в самия него. Ключовете са на български нарочно; съдържанието се пише от
хора, не от програмисти.

---

## 2. Скриптът

`src/import-product.ts`, пуска се така:

```
npm run import:product delta-3-classic
```

Добави реда в `package.json`:
```json
"import:product": "payload run src/import-product.ts"
```

### Какво прави, по ред

**1. Чете JSON-а.** Ако папката или файлът липсват — спира с ясно
съобщение, не създава нищо.

**2. Качва изображенията в Медия.**
- Всяко изображение получава `alt` от полето `imageAlt` (за секциите)
  или `alt` (за галерията)
- **Проверява по име дали вече е качено.** Ако файл със същото име
  съществува в Медия, ползва съществуващия запис, не качва копие.
  Скриптът трябва да може да се пуска няколко пъти без да трупа дубликати
- Ако файл, посочен в JSON-а, липсва на диска — записва предупреждение,
  оставя полето празно и продължава. Не спира целия внос заради една
  липсваща снимка

**3. Намира категорията** по `categorySlug`. Ако я няма — спира със
съобщение кои категории съществуват.

**4. Създава или обновява продукта.**
- Търси по `slug`. Ако съществува — обновява го. Ако не — създава нов
- Полетата от `produkt` отиват директно
- `galeriya` → полето `gallery`
- `specGroups` → полето `specGroups`
- `sekcii` → полето `sections`, като всеки запис става блок със своя
  `blockType`
- Първата снимка от `galeriya` става `image` (основната), останалите
  влизат в `gallery`

**5. Изписва обобщение накрая:**
```
✓ Качени нови изображения: 12 (пропуснати вече съществуващи: 6)
✓ Продукт: EcoFlow DELTA 3 Classic (обновен)
✓ Секции: 14
⚠ Липсващи файлове: 1 — 12_97c59bb8....webp
```

## 3. Важно: продуктите нямат чернови

Проверих — колекцията `products` няма `versions: { drafts: true }`, за
разлика от `pages`. Означава, че внесеният продукт **излиза наживо
веднага**.

За един продукт локално няма значение. За внасяне на 45 наведнъж има.

**Затова добави чернови на `products`:**
```ts
versions: { drafts: true }
```

И в `src/lib/payload.ts` — заявката за продукти да филтрира
`_status: 'published'`, както вече е за страниците. Ако няма такава
заявка, добави я на мястото, откъдето продуктовата страница чете.

Скриптът да създава продукта **като чернова** (`draft: true`), за да може
собственикът да го прегледа и чак тогава да натисне „Публикувай".

**Внимание:** съществуващите 16 продукта ще станат невидими, докато не
бъдат публикувани. Това е очакваното поведение — отбележи го в изхода на
миграцията или ми кажи, за да го публикуваме наведнъж.

---

## 4. Правила

- **Никакви нови зависимости.** `fs/promises` и вграденият API на Payload
  стигат
- Скриптът да е **повторяем** — второ пускане да обновява, не да дублира
- Съобщенията на български
- Не пипай нищо извън `src/import-product.ts`, `package.json`,
  `src/collections/Products.ts` и `src/lib/payload.ts`

**След промяната в схемата:**
```
npm run generate:types
npm run migrate:create
```

---

## 5. Как да разбереш, че е готово

- `npm run import:product delta-3-classic` минава без грешка
- В админа се появява „EcoFlow DELTA 3 Classic" със статус чернова
- В раздел „Секции на страницата" има 14 секции в реда от JSON-а
- Галерията има 8 снимки, първата е и основната
- Спецификациите са в 9 групи
- Второ пускане на същата команда **не** създава втори продукт и **не**
  качва снимките наново
- Пускане с несъществуваща папка дава ясно съобщение, не срив
