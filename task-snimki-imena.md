# Задача: смислени имена на всички снимки — навсякъде

Прочети целия файл преди да започнеш.

**Изпълни я СЛЕД** като:
- е пусната замяната с прозрачните снимки (`npm run snimki:zameni`);
- е готова задачата `task-seo-tehnichesko.md`.

Сайтът още не е публичен, така че сега е най-доброто време — няма стари адреси в Google, които да се чупят.

## Целта
Много снимки са с безсмислени имена: `ddsds.webp`, `sddled.webp`, `61569_2.webp`, `untitled-1_1_18_1.webp`, `xt60iiid.webp`. Искаме **всички** снимки да получат смислено име **веднъж и навсякъде**:
- в медията на сайта;
- в съдържанието (`content/`);
- в преведените и обработените файлове;
- във всички линкове по страниците.

Целта е след смяната да има **само едно име** за всяка снимка — без двойна система „старо/ново“ и без празни или объркани снимки.

## 1. Новите имена
Само малки латински букви, цифри и тирета, без интервали. Разширението е на реалния файл.

| Снимка | Ново име | Пример |
|---|---|---|
| Галерия на продукт | `<slug>-<позиция>` | `glacier-plug-in-battery-1.webp`, `…-2.webp` |
| Секция на продукт | `<slug>-<anchor на секцията, транслитериран, или sekciya-N>-<N>` | `single-axis-solar-tracker-preglad-1.jpg` |
| Една снимка в няколко продукта (същият media запис) | по **първия** продукт, който я използва (по `_order`) | `relay-module-6a-1.webp` |
| Снимка извън продуктите (банери, начална страница, „За EcoFlow“, иконки) | транслитериран alt текст; ако няма alt — по мястото, където се ползва | `za-ecoflow.jpg`, `banner-sezon-na-burite.webp` |

- Ако името е заето → `-2`, `-3`…
- Снимките, които вече са смислени, също минават през правилото — за еднообразие.

## 2. Какво се сменя — навсякъде
Едно пускане сменя името на всички места:

1. **Медията:**
   - файлът и всичките му размери/webp варианти;
   - записът в Media (`filename`, url);
   - `id` и `alt` остават същите.
2. **Всички връзки в базата:**
   - продукти — галерия, секции, `inTheBox`, табове, OG снимка;
   - категории — банер, hero;
   - менюта и панели;
   - начална страница;
   - globals.

   Повечето са по `id` и не се променят. **Всичко, което сочи по път или име** (rich text, JSON полета, url в текст, CSS фонове, хардкоднати пътища в кода), се намира и обновява.
3. **`content/<slug>/sadarzhanie.json`:**
   - `galeriya[].file` и всички `image` в `sekcii` → новите имена;
   - `_svali_snimki` става списък от `{"url": "<оригиналният адрес в dice/EcoFlow>", "file": "<новото име>"}`. Така вносът сваля от същия адрес, но записва под новото име.
4. **`content/<slug>/prevod-nadpisi.md` и `snimki-za-svalyane.txt`** — новите имена.
5. **`content/snimki/`:**
   - преведените и прозрачните файлове се **преименуват** с новото име;
   - разширението си остава — `.png` си е `.png`.
6. **Кодът** — ако някъде в `src/` има хардкоднато име на снимка, обнови го.

Запази таблицата на смяната като `content/snimki-imena.csv` (старо име | ново име | продукт/място | къде) — **в git**, за справка.

Поле „Оригинално име“ в Media **само за справка** (кой е бил източникът). Вносът и замяната вече **не търсят** по него — търсят по новото име.

## 3. Как се пуска
- `npm run snimki:imena -- --dry-run` → само CSV-то, нищо не се сменя. **Прати ми го, преди да пуснеш истинската смяна.**
- `npm run snimki:imena` → сменя всичко от т. 2 и опреснява кеша. Адресите на снимките получават нов `?v=`.
- Направи backup на базата и на `content/` преди истинското пускане (както при миграциите).
- Скриптът може да се пуска пак без вреда: снимка с правилното име не се пипа.

## 4. Новите снимки занапред
- При внос (`import:product`, `import:all`) новите снимки се записват **направо** с името по т. 1. В `_svali_snimki` се пише `{url, file}`.
- В `prevod-nadpisi.md` и `za-prevod/spisak.md` вносът пише **новите** имена. Собственикът слага преведените и обработените файлове в `content/snimki/` **под новото име**.
- Ако в `content/snimki/` има файл, който не съвпада с нито една снимка — вносът да го отчете в изхода (а не да го пропусне тихо).

## 5. Проверка — да няма празни или объркани снимки
- **Обходи всички страници от sitemap** + началната:
  - всеки `<img>`, `srcset`, `og:image`, JSON-LD `image` и CSS фон връща **200**;
  - нито една снимка не е 404 или празна;
  - пиши ми броя проверени снимки и грешките (трябва да са 0).
- **5 продукта** (`glacier-plug-in-battery`, `relay-module-6a`, `extra-battery-cable-5m`, `single-axis-solar-tracker`, `delta-3-plus`): правилните снимки са на правилните места, alt е същият, а преведените и прозрачните версии са запазени.
- `npm run import:all -- --dry-run` — без промени по снимките. Нищо „ново“, нищо „липсващо“.
- **Тест на замяната:** файл в `content/snimki/` под **новото** име на една снимка → отива на мястото ѝ. После върни, както е било.
- Image sitemap показва новите адреси.
