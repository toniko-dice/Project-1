# Задача: вносът да сваля снимките сам

Сега собственикът сваля всяка снимка на ръка по `snimki-za-svalyane.txt`.
При 30 снимки на продукт и 40 продукта това е най-бавната стъпка.
Адресите вече са в `sadarzhanie.json` → `_svali_snimki.galeriya[]` и
`_svali_snimki.sekcii[]` (пълни https адреси; името на файла е
последният сегмент от адреса, без `?…`).

## 1. Правило

При внос (`import:product` и `import:all`), за всеки файл, който
продуктът ползва (галерия, секции, кутия):

1. ако файлът е в `content/<slug>/galeriya/` или `sekcii/` → ползва се
   той (както досега; ръчно преведена снимка има предимство);
2. иначе, ако файл със същото име е в Медия → преизползва се (както
   досега);
3. иначе, ако името е в `_svali_snimki` → **сваля се** в
   `content/<slug>/galeriya/` или `sekcii/` (според списъка) и после се
   качва по правило 1;
4. иначе → предупреждение „липсва файл“, както досега.

Свалянето: `fetch` с `User-Agent` на браузър, 3 опита, 30 s таймаут;
записва се байт по байт (без преобразуване); ако сървърът върне
WebP под .jpg име — оставя се (вносът вече разпознава по съдържание).
Паралелно до 4 файла наведнъж. Грешка при един файл не спира
продукта — секцията остава без снимка и се изписва в обобщението.

`--no-download` изключва свалянето (само локални файлове и Медия).

## 2. dice.bg

Адресите на dice са `https://cdn.dice.bg/media/…/<ean>-N_1.webp` — същото
правило, нищо специално.

## 3. Проверка

Изтрий `content/river-3-max/galeriya/` (6 файла) и пусни
`npm run import:product river-3-max` → папката се създава наново със
същите 6 файла, продуктът е с галерия. Изпиши в CLAUDE.md: снимките се
свалят при внос; ръчно преведените в `sekcii/` имат предимство и не се
презаписват.

## 4. Git

Commit + push (папките със снимки остават в `.gitignore`).
